1. Sistema de Gestión de Calidad (SGC)

Un conjunto de políticas, procesos y procedimientos que una organización implementa para asegurar que sus productos o servicios cumplan con los requisitos del cliente y mejoren de forma continua. En desarrollo web, se aplica para asegurar que los procesos, desde la planificación hasta la entrega, sigan estándares de alta calidad.

2. Ciclo de Vida del Software

Un modelo que describe las fases de un proyecto de software, desde la concepción hasta el desuso. Incluye fases como requisitos, diseño, implementación, pruebas y mantenimiento. Un enfoque en la calidad en cada etapa garantiza un producto final robusto y confiable.

3. Manual de Calidad

Un documento que describe el sistema de gestión de calidad de una organización. Define la política de calidad, los objetivos, la estructura organizacional y las responsabilidades, sirviendo como una guía para todos los miembros del equipo.

4. Objetivos de Calidad

Metas medibles y específicas que una organización establece para su desempeño en materia de calidad. Deben ser consistentes con la política de calidad y a menudo se centran en mejorar la satisfacción del cliente, reducir defectos y optimizar los procesos.

5. Política de Calidad

La declaración formal de la dirección de una organización sobre sus intenciones y dirección en relación con la calidad. Es un compromiso con la mejora continua y el cumplimiento de los requisitos de los clientes y reglamentarios.

6. Proceso de Desarrollo de Software

El conjunto de actividades, métodos y prácticas que se utilizan para crear un producto de software. La aplicación de la calidad en este proceso asegura que cada etapa contribuya a un producto final que cumpla con los estándares.

7. Normas ISO

Estándares internacionales que definen los requisitos para los sistemas de gestión de calidad en diversas industrias, incluyendo el desarrollo de software. Un ejemplo relevante es la ISO 9001, que certifica que una empresa tiene procesos de calidad rigurosos.

8. Plan de Calidad del Software

Un documento que especifica los estándares, prácticas, recursos, actividades y mediciones de calidad que se aplicarán a un proyecto de software. Sirve como una hoja de ruta para el equipo de desarrollo, asegurando que se mantengan los niveles de calidad acordados.

9. Auditoría de Calidad

Un examen sistemático e independiente para determinar si las actividades y los resultados relacionados con la calidad cumplen con las disposiciones planificadas, si estas disposiciones se implementan de manera efectiva y si son adecuadas para alcanzar los objetivos.

10. Aseguramiento de Seguridad

Un proceso que garantiza que los sistemas, datos e información estén protegidos contra accesos no autorizados, daños o interrupciones. En el contexto de la calidad, implica la integración de prácticas de seguridad en el ciclo de vida del software para prevenir vulnerabilidades.

11. Control de Calidad

El conjunto de actividades operativas utilizadas para cumplir con los requisitos de calidad. Se enfoca en la identificación de defectos en el producto terminado, como la validación de un módulo HTML para asegurar que no tenga errores y que funcione correctamente.

12. Acciones Preventivas

Medidas tomadas para eliminar la causa de una no conformidad potencial u otra situación indeseable antes de que ocurra. Por ejemplo, la revisión del código por pares puede ser una acción preventiva para evitar futuros errores en un módulo HTML.

13. Acciones Correctivas

Medidas tomadas para eliminar la causa de una no conformidad existente o un defecto. A diferencia de las acciones preventivas, estas se aplican después de que se haya detectado un problema, como corregir un error en un script que afecta el rendimiento de un sitio web.

14. Indicadores de Calidad

Métricas que se utilizan para medir y evaluar el desempeño de los procesos y productos en relación con los objetivos de calidad. Ejemplos incluyen el número de defectos por línea de código o el tiempo promedio de respuesta del servidor.

15. Gestión de Riesgos

El proceso de identificar, evaluar y priorizar los riesgos, y luego aplicar los recursos de manera coordinada para minimizar, monitorear y controlar la probabilidad o el impacto de eventos desafortunados. En el desarrollo de software, se utiliza para anticipar y mitigar problemas que podrían afectar la calidad.

16. Métricas de Calidad del Software

Medidas cuantitativas que evalúan las características de un producto de software o de los procesos involucrados en su desarrollo. Permiten a los equipos tomar decisiones basadas en datos para mejorar la calidad.

17. Cobertura de Código

Una métrica de calidad que mide el porcentaje del código de un programa que es "ejecutado" por las pruebas automatizadas. Una alta cobertura de código es un indicador de que el software ha sido probado exhaustivamente.

18. Mantenimiento del Software

El proceso de modificar y actualizar el software después de su entrega, ya sea para corregir errores, mejorar el rendimiento o adaptar el producto a un nuevo entorno. Un buen mantenimiento es crucial para la calidad a largo plazo.

19. Error de Código

Un "bug" es un error, falla o defecto en un programa de computadora que produce un resultado incorrecto o inesperado. La detección y corrección de errores son componentes clave del control de calidad.

20. Estándar de Calidad

Un conjunto de criterios o requisitos que deben cumplirse para que un producto, servicio o proceso sea considerado de alta calidad. Son las reglas por las que se rige el desarrollo, como los estándares de codificación para HTML.

21. Tasa de Defectos

Una métrica de calidad que calcula el número de defectos encontrados en un producto de software por unidad de medida (por ejemplo, defectos por 1000 líneas de código). Una tasa baja indica un producto de mayor calidad.

22. Tiempo de Ciclo

El tiempo total que transcurre desde el inicio de un proceso hasta su finalización. En el desarrollo de software, un tiempo de ciclo más corto puede indicar una mayor eficiencia, siempre y cuando no se sacrifique la calidad.

23. Tasa de Retención de Usuarios

Mide el porcentaje de usuarios que continúan utilizando un producto a lo largo del tiempo. Una alta tasa de retención es un fuerte indicador de que el software es de alta calidad y satisface las necesidades de los usuarios.

24. Aseguramiento de la Calidad (QA)

El conjunto de actividades planificadas y sistemáticas implementadas en el marco del sistema de calidad para proporcionar la confianza de que un producto o servicio cumplirá con los requisitos de calidad. Se enfoca en prevenir defectos.

25. Pruebas

El proceso de ejecutar un sistema o componente con el objetivo de encontrar errores. Es una parte crucial del control de calidad, ya que valida que el software funciona como se espera y cumple con todos los requisitos.
